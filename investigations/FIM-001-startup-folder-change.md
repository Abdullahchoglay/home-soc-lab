# Investigation FIM-001 — Startup Folder File Change

## Summary

Wazuh detected the creation, modification, and deletion of a text file in the
Windows shared Startup directory. The activity was generated as a controlled,
harmless validation of file integrity monitoring on `WIN-ENDPOINT-01`.

## Detection Details

- **Agent:** `WIN-ENDPOINT-01`
- **Agent ID:** `001`
- **Monitoring mode:** Real time
- **File:** `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup\wazuh-fim-current-test.txt`
- **Test date:** 2026-09-17

| Time (UTC) | Rule | Level | Event |
|---|---:|---:|---|
| 15:49:52 | 554 | 5 | File added to the system |
| 15:50:07 | 550 | 7 | Integrity checksum changed |
| 15:50:22 | 553 | 7 | File deleted |

## Analysis

The Startup directory is security-sensitive because files placed there can run
when a user signs in. Wazuh detected each stage of the test in real time. The
modification alert recorded changes to the file size, modification time, and
MD5, SHA-1, and SHA-256 checksums. In a real incident, unexpected deletion can
be reviewed for possible T1070.004 (File Deletion) behavior, but this authorized
test does not by itself establish malicious intent or an ATT&CK technique.

The filename and timestamps match the authorized lab procedure. No executable
payload was used, and the temporary file was removed after testing.

## Verdict

**Benign true positive.** The activity was intentionally generated by the lab
owner to validate Wazuh file integrity monitoring.

## Response

- Confirmed the activity was authorized.
- Verified all three FIM lifecycle events reached the Wazuh manager.
- Confirmed `WIN-ENDPOINT-01` remained active.
- Removed the temporary test file.
- No containment or remediation was required.

## Lessons Learned

- Wazuh successfully monitors the shared Windows Startup directory in real time.
- File hashes and metadata help distinguish modifications from simple creation.
- An alert can be a true detection while still being benign after investigation.
